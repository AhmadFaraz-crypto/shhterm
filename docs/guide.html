shhterm Documentation

End-to-end encrypted chat for your terminal and the browser. No accounts, no email, no passwords — a room key is the only credential.

Overview

shhterm lets people chat in real time from a terminal or a web browser. You create a room, get a secret room key, and share it. Anyone with the key joins the room and can send and receive messages. Message contents are end-to-end encrypted — the server only relays ciphertext and cannot read them.

  • No sign-up — the room key is the credential.
  • Ephemeral — nothing is stored or logged; empty rooms vanish after 5 minutes.
  • Everywhere — terminal (macOS/Linux/Android/WSL) and any browser (including iPhone).

How it works

shhterm is client–server: everyone connects to one server, which routes messages between members of a room. Clients never connect directly to each other.

  You ─┐                          ┌─ Friend
       ├──►  shhterm server  ◄──┤
  Web ─┘    (relays ciphertext)   └─ Terminal

The room key has two halves:

  • a routing half the server uses to find the room, and
  • a secret half that never leaves the clients and is used to derive the message-encryption key.

Because the server only ever receives the routing half, it can relay messages but cannot decrypt them. A browser user and a terminal user in the same room can read each other perfectly — they use the same encryption scheme (AES-256-GCM, key derived via HKDF-SHA256).

You need a running server to chat. Use the public community server (built into the apps), or host your own.

Getting started

🌐 Browser (any device, including iPhone)

Nothing to install. Open shhterm.duckdns.org, then Create or Join a room. This is the easiest way, and the only option on iPhone/iPad.

💻 Terminal (macOS / Linux)

# 1. Install dependencies
#    macOS:   brew install cmake ninja boost openssl@3
#    Ubuntu:  sudo apt-get install -y build-essential cmake ninja-build libboost-dev libssl-dev git

# 2. Clone & build
git clone https://github.com/AhmadFaraz-crypto/shhterm && cd shhterm
cmake -S . -B build -G Ninja      # macOS: add -DCMAKE_PREFIX_PATH=$(brew --prefix) -DOPENSSL_ROOT_DIR=$(brew --prefix openssl@3)
cmake --build build

# 3. Chat (uses the public server by default — no flags needed)
./build/shhterm create --name YourName

📱 Android (Termux)

Install Termux from F-Droid (not the Play Store), then:

pkg update -y && pkg install -y clang cmake ninja git openssl boost boost-headers
git clone https://github.com/AhmadFaraz-crypto/shhterm && cd shhterm
cmake -S . -B build -G Ninja -DSHHTERM_BUILD_TESTS=OFF
cmake --build build --target shhterm
./build/shhterm create --name YourName
Install both boost and boost-headers — otherwise the build fails with 'boost/asio/executor_work_guard.hpp' file not found.

🪟 Windows

Use WSL: run wsl --install in an Administrator PowerShell, reboot, then follow the Ubuntu steps inside the Ubuntu shell.

Rooms & keys

Create a room to start a new conversation; join one with a key someone shared.

shhterm create --name Ahmad          # creates a room, prints a key
shhterm join <room-key> --name Ali   # joins an existing room
  • The room key carries 256 bits of randomness and is the only thing protecting a room — treat it like a password.
  • Keys are case-insensitive and forgiving of spaces/dashes, so they're easy to paste.
  • Multiple people can be in one room, and you can run many independent rooms at once.
  • Names must be unique within a room; pick another if yours is taken.

Sharing a room

Once you're in a room you have three easy ways to invite someone:

MethodWhat it does
/inviteCopies a ready-to-send join command (terminal) or a …/room/<key> link (browser) to your clipboard. The recipient just changes the name.
/copyCopies just the room key.
Browser buttonsThe web client shows Copy link / Copy key next to the key.

A room link like https://shhterm.duckdns.org/room/<key> pre-fills the key — the person just enters a name and clicks Join. It even works to a terminal user: they use the key with shhterm join.

Commands

Type these in the message box (they start with /). Available in both the terminal and the browser.

CommandEffect
/invite [name]Copy a shareable join command / link (optionally pre-filling a name).
/copyCopy the room key to the clipboard.
/clearClear your own chat view (doesn't affect anyone else).
/theme <name>Change the color theme (terminal only). See Themes.
/usersList everyone currently in the room.
/nick <name>Change your display name.
/msg <user> <text>Send a private (direct) message to one person in the room.
/helpShow the command list.
/quitLeave the room and exit (terminal: also Ctrl-C / Ctrl-D).
/msg is routed to one recipient and is private from the server, but it uses the shared room key — so it isn't cryptographically private from other room members.

Themes

The terminal UI has six color themes. Switch live with /theme <name>, pick one at launch with --theme <name>, or set theme = <name> in your config file.

NameLook
darkNavy + green (default)

Type /theme with no name to list them and see the current one. Truecolor themes look best in a terminal with 24-bit color support.

Config file

To avoid passing flags every time, create ~/.shhtermrc:

name = Ahmad
server = your.server:8443      # optional; overrides the built-in default
ca = /path/to/server.crt       # only for self-signed servers
verify_host = your.server
theme = ocean

Then just run shhterm create or shhterm join <key>. Command-line flags and the SHHTERM_SERVER environment variable override the file.

Command-line options

FlagMeaning
--name <name>Your display name (required).
--server <host:port>Server address (overrides the built-in default).
--theme <name>Start in a specific theme.
--ca <file>Trust a specific certificate (self-signed servers only).
--verify-host <name>Hostname/IP to verify in the server certificate.
--insecureDev only — skip certificate verification. Never use against a real server.

Status & delivery

The status bar shows whether you're connected, reconnecting…, or disconnected, plus a 🔒 e2e badge and who's online.

Each message you send shows a delivery mark:

·Sent, waiting for the server to acknowledge it.
✓The server accepted and routed it.
✗ not deliveredThe connection dropped before it was acknowledged — it was not delivered.

shhterm never falsely claims delivery. If the connection drops, the client reconnects automatically with increasing back-off and shows when it's back. Thanks to the 5-minute empty-room window, a brief blip won't lose your room.

Security & privacy

Protected: message bodies are end-to-end encrypted (AES-256-GCM; the key is derived from the room key's secret half, which never reaches the server). Transport is TLS. Nothing is persisted or logged.
Not hidden: metadata the server must act on — usernames, who is in a room, and message size/timing. E2E protects contents, not metadata.
  • The room key is the only credential. Anyone with the full key can join and decrypt — share it over a channel you trust.
  • One key per room, used for the room's lifetime (no rotation / forward secrecy).
  • Direct messages (/msg) are private from the server but not from other room members.
This is a hobby/educational project without a formal security audit. It's great for private, casual chats — don't rely on it for high-stakes confidentiality. See SECURITY.md.

Self-hosting

The public community server is best-effort with no uptime guarantee. Run your own for a private, reliable server. On a fresh Ubuntu/Debian VPS it's one command:

git clone https://github.com/AhmadFaraz-crypto/shhterm && cd shhterm

# With a domain (trusted cert, clients need no flags):
sudo ./scripts/install-server.sh chat.example.com

# Or with no domain (self-signed cert for this box's public IP):
sudo ./scripts/install-server.sh

Then point clients at it with --server your.host:8443, or bake it in at build time with -DSHHTERM_DEFAULT_SERVER=your.host:8443. For the web client, IP-only, and a LAN-only (same-office, no internet) setup, see DEPLOYMENT.md.

FAQ

Can I use it on my iPhone?

Yes — use the web client in Safari. iOS can't run terminal apps, but the browser client shares rooms and encryption with terminal users.

My friend and I are in the same office — how do we connect?

Easiest: both open the web client, one creates a room and hits Copy link, sends it, the other joins. (Being on the same network isn't required — you both reach the server over the internet.) For a fully offline, same-network setup see the LAN option in DEPLOYMENT.md.

Do both people need to install anything?

For the browser, no. For the terminal app, each person needs the shhterm client built on their machine. Either way you both connect to the same server.

Is my chat stored anywhere?

No. Messages live only in server memory for the instant they're relayed, are never written to disk or logged, and there's no history — someone joining later can't see earlier messages.

Can the server operator read my messages?

No — message bodies are end-to-end encrypted; the server only sees ciphertext. It can see metadata (who's in a room, timing). For a guarantee you fully control, host your own server.

What if the server is down?

The public server is best-effort. Clients auto-reconnect when it's back. For reliability, run your own.
